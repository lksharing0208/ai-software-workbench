# 项目资料存储

工作台负责维护可复用资产。业务仓库保存项目事实、任务历史和运行证据。新增资料时，先判断下一次维护这份资料的人应在哪个仓库更新它。

| 资料 | 维护位置 | 维护方式 |
|---|---|---|
| 主控、路由、能力指令 | 工作台 `skills/<id>/SKILL.md` | 一项能力一个稳定 ID。专属参考放同目录 references/，随 Skill 一起分发 |
| 客户端配置、示例与打包 | 工作台 `clients/`、`.codex/agents/`、`.claude-plugin/`、`scripts/` | 客户端只保存加载格式、工具配置和分发差异。生成的 ZIP 在本地 dist/ |
| 团队研发流程、来源、通用提示词 | 工作台 `docs/`、`prompts/` | 长期规则在文档维护，启动提示词只提供当次输入和交付要求 |
| 任务、审查、发布的空白表单 | 工作台 `templates/`、`.github/` | 模板只维护字段。Issue / PR 已记录的内容在任务中引用其链接 |
| 项目长期资料 | 目标业务仓库现有规范目录 | 项目适配器登记仓库、分支、模块图、技术栈、规范入口、数据边界及验证命令。API、DDL 和架构决定随对应源码版本维护 |
| 在办任务 | 业务仓库 `tasks/active/<task_id>/` 或该项目既有任务根 | task.md 记录目标、范围和验收，checkpoint.md 保存当前进度；按需增加 design.md、review.md、delivery.md |
| 原始运行证据与构建产物 | 业务项目已有 CI、制品库或受控日志系统 | 在任务中登记提交、命令、结果及证据链接。共享记录使用脱敏摘要 |
| 已结束任务 | 同一业务仓库 `tasks/archived/<task_id>/` | 完成或取消后整目录迁移，保留任务 ID、决定、审查版本和遗留项 |

## 一个跨仓任务如何落盘

例如一次 API 字段变更同时涉及前端和后端，在负责契约的业务仓库登记一个任务 ID。task.md 列出两个仓库、基线和各自验收条件；design.md 链接契约与调用方；review.md 按仓库记录实际差异与整改提交。两边的 PR 回链到同一任务。归档时补齐两个交付提交，避免每个仓库各维护一份规格。

新项目可从[项目适配器模板](../projects/adapter-template.md)起步。已有资料目录可直接登记路径，接入时无需搬动既有工程文档。

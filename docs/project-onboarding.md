# 现有业务仓库接入与质量门禁

先在业务仓库登记[项目适配器](../projects/adapter-template.md)。合并已有的 AGENTS.md、CLAUDE.md 和 Issue/PR 模板，保留项目约定。选一个小变更，从需求、差异、验证证据到交付跑通一轮。

| 接入项 | 需要登记或验证 |
|---|---|
| 工程基线 | 目标提交、依赖与运行时版本、模块入口、已有开发与发布规范 |
| 客户端访问 | 用指定提交读取一个文件，再独立核对 PR 差异、仓库写入与执行环境各自的权限 |
| 本地验证 | 从真实构建定义提取命令。例如 Maven 工程核实 Wrapper 后用 ./mvnw verify；Node 核对锁文件和 package.json 中的脚本；Python 读取项目定义及已有测试入口 |
| 验证范围 | 按改动选择静态检查、单元、集成、契约或端到端验证，登记环境、命令、结果与遗漏。缺少测试脚本时记录缺口 |
| CI 接入 | 由业务项目决定是否启用。将验证过的命令映射为状态检查，限制工作流权限，避免向外部 PR 暴露发布凭据 |
| 上线与回退 | 事先记录制品、健康检查、业务阈值、回滚对象与决策人，按[发布与回滚手册](release-and-rollback.md)执行 |

# 从需求到交付

| 阶段 | 必要输入 | 交给下一阶段的材料 |
|---|---|---|
| 登记与需求 | 目标、目标仓库、现状证据 | 任务范围、验收标准、基线与允许修改的文件 |
| 概要设计 | 已确认需求、项目规范 | 模块责任、接口边界、备选方案、影响与设计审查结论 |
| 详细设计 | 已审概要和当前源码 | 字段与状态流、事务及错误处理、兼容与回退；核对调用方后登记设计版本 |
| 实现 | 已确认规格、实际工作区 | 修改文件、提交或真实 diff、实现与设计的差异 |
| 代码审查与整改 | 需求、差异、调用链 | 每项发现的证据、影响、处理与复审版本。按 code-review 的统一等级登记 |
| 验证与交付 | 验收条件、项目允许的检查 | 实际命令及结果、未验证项、交付提交。涉及发布时另记录制品、监控指标、回滚条件与负责人 |
| 复盘与归档 | 交付记录、遗留项 | 验收结果、返工原因及后续负责人，按任务 ID 归档 |

## 检查点与恢复

任务状态描述整项工作。登记为 PENDING，执行时为 RUNNING；缺输入为 WAITING_INPUT，待决策为 WAITING_APPROVAL，主动暂停为 PAUSED，执行失败为 FAILED。完成与取消分别记为 COMPLETED、CANCELLED。阶段另记进行中、待修订或已通过。审查要求修改时保留任务，返回受影响阶段。

阶段完成、用户决策、失败或交接时更新 checkpoint.md，保留唯一 next_action。恢复时先核对任务 ID、目标分支、基线提交、未提交差异和最后证据。发现其他人已改动文件，先检查影响。重试远端写入前核对实际结果。

## 选择验证方式

按任务单登记执行范围。静态审查检查源码、差异及契约，交付记录注明未运行的验证。允许执行验证时，按改动选择构建、单测、集成或人工验收，分别附命令、环境和结果。发布按业务项目自身的流程另行执行。只读评审任务止于审查结论。

使用[审查模板](../templates/review.md)、[发布检查单](../templates/release.md)和[复盘指标](retrospective.md)记录对应阶段。

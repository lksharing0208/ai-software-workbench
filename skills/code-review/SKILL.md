# Code Review

## 范围
默认只审查本次变更。先看 Diff，再按需读取相关上下文；历史问题仅在影响当前变更时报告。

## 检查项
- 需求覆盖、正常/异常/边界路径、状态转换、空值和幂等。
- Java/Spring 分层、Bean、异常、NPE、事务和并发（适用时）。
- SQL 条件、参数映射、UPDATE/DELETE、逻辑删除、N+1 和索引（适用时）。
- 鉴权、越权、注入、敏感信息、日志凭证和输入校验。
- 性能退化、资源泄漏、重复调用、可维护性和测试缺口。

## 严重等级
- Blocker：可能导致严重越权、数据损坏、核心流程不可用。暂停交付，记录决策。
- Major：正常或合理边界下产生错误、回归或不一致。修复后按新 diff 复审。
- Minor：影响局限，记录修复或接受理由。
- Info：建议项，由维护者安排。

独立审查输入包含基线与待审提交、验收条件、实际差异和调用链。实施者自检另行标注。记录已检查范围与未验证部分；无未关闭 Blocker/Major 方可通过。

## 每条问题必须包含
- 文件路径和代码位置
- 问题及触发条件
- 业务/安全/运行影响
- 修改建议
- 可验证证据

## 规则
- 以代码事实为依据，不制造风格问题。
- 不重复报告同一根因。
- 未读取的代码不得作为问题证据。
- 无问题时明确输出“未发现需要修复的问题”。

# 研发协调器

先确认交付物、目标项目、分支、基线和允许的操作。已有任务先核对检查点、当前提交和未提交差异。简单解释直接作答；明确的单项任务直接进入对应能力。需要分级时读取[主控配置](references/manifest.yaml)，意图不明确时调用 intent-router。

1. 按需装配上下文。优先读项目规范、入口、上下游调用方、契约及已有测试。用路径和符号传递证据。
2. 跨阶段变更依次处理需求、概要设计与审查、详细设计与审查、实现、代码审查、验证及交付。已有确认产物可直接引用并登记基线。单点任务只执行适用阶段。
3. 同一批文件指定一个主修改者。审查者读取真实差异；收到修订后以新提交复查。区分独立审查、阶段自检和实际运行结果。
4. 按项目约束决定可执行的检查。只允许静态审查时列明未运行项。需负责人作取舍时调用 human-gate，记录决定、影响和唯一下一步。
5. 交接保留目标、事实、文件、决定、风险和下一步。跨会话任务在业务仓库维护任务单与检查点；完成后按原任务 ID 归档。
